# 知识库与百舸文库需求交接（数据摆渡前置资料）

更新日期：2026-11-14  
适用项目：百舸数智平台原型 · `proj-codex` 当前工作区  
用途：在同一项目的新对话中设计「数据摆渡」时，作为两套资料业务的现状基线、约束和验收资料。

## 0. 新对话怎么使用这份文档

在同一项目空间开新对话，发送下面这段话即可：

> 请先完整阅读 `docs/知识库与百舸文库需求交接.md`，它是当前知识库和百舸文库的业务基线。我要在本项目设计数据摆渡。先确认摆渡方向、源端和目标端、允许进入目标端的数据范围，以及目标端审核与发布规则。项目原型里的演示状态、权限规则和已知缺口请分别对待。先给我可确认的方案，再按我确认的范围实施。

**阅读口径**：「已确认」指用户已明确、或纳入《DESIGN.md》的既有需求。「当前实现」指在工作区代码可定位的原型行为，包括演示和未完成入口。「待确认」指摆渡项目须由业务方选择的规则。若文档指出二者有落差，验收应以用户已确认的业务规则为准并明确补齐范围。页签、按钮、样例数据或本地存储只能说明原型做了什么。

## 1. 产品范围和业务边界

| 用户从哪里进入 | 查找或管理的对象 | 主要动作 | 当前数据来源 |
| --- | --- | --- | --- |
| 客户端「知识库」 | 行业、企业、部门三个公共知识库分类，以及个人上传文档列表 | 按库名和所属组织找资料；个人文档看状态、编辑和删除；公共库点击预留独立问答入口 | 公共目录来自 `BaigeData.knowledgeDirectory`；个人文档是页面内演示记录 |
| 客户端「百舸文库」 | 按八种类型组织的单篇文档 | 热门、最新、关键词／AI 检索、在线阅读、下载权限提示、单文档问答 | `BaigeLibraryStore` 的文档记录；正文与问答使用示例 |
| 后管端「百舸文库 → 文件管理／权限管理」 | 按管理部门职责划分的文库文档及对部门、人员的访问授权 | 上传、模拟涉密检测与解析、查看审查详情、维护清单；为目标部门／个人调整文档权限 | 与客户端百舸文库使用同一文库数据模型及浏览器存储 |
| 百舸问答的知识选择器、个人中心权限申请、后台权限审核、角色授权审核 | 各自的知识来源、功能与部门数据申请、账号角色权限 | 选来源提问、申请或审许可 | 独立的数据模型，见「权限与问答的边界」 |

几个容易混淆的名称：

- **知识库**是分类资料索引，公共项的主对象是一座知识库；**百舸文库**以一篇文档为主对象，按文档类型、来源、归属部门和访问方式管理。
- **公共知识库**在此文指前台展示的行业、企业、部门三类目录，相对个人文档使用。实际可访问范围仍要区分用户、组织、数据授权，不能把「公共」视为全员可读或可对外传输。
- **全部公开／有限公开**是文库文件的公开方式；有限公开文档的某个对象也可收到名为「全部公开」的特殊授权。两者作用域分别是文档、单个对象。
- **涉密审查、内容解析、访问权限**是不同维度。涉密判定决定能否继续进入业务流程，解析状态反映处理进展，访问授权决定给谁看、看多少、能否下载。
- **本部门**在文库权限计算里指该文档的归属管理部门。文库管理部门、授权对象部门、前台知识库组织分组、三元权限的组织实例需要分别识别。
- 当前工作区未检出既有「数据摆渡」、网间交换任务、导入导出协议或跨环境映射实现。拟建范围从第 6 节的问题清单开始确认。

## 2. 前台知识库

### 2.1 产品定位和入口

- 知识库是客户端的资料索引。行业、企业、部门三个分类展示**库卡片**，个人文档分类直接展示**个人文件**。用户曾确认个人区直接展示个人上传的文档，以资料列表为主，点击具体公共库后进入独立问答页的方案留待后续。
- 控制台从 `index.html#knowledge` 进入。侧栏位于「知识与研究」分组，一级菜单叫「知识库」，路由键为 `knowledge`，页面是 `pages/knowledge.html`。默认「行业知识库」。独立页面支持 `#industry`、`#enterprise`、`#department`、`#personal` 初始化指定分类。分类切换写入当前知识库页面的哈希，外壳保留该模块 iframe，因此同一 iframe 在菜单切换期间可以保留内存状态。
- 公共库卡片和个人文档分别使用不同的数据结构和业务入口。公共库卡片点击后只提示「已选择『库名称』，独立知识问答页面待接入」；没有库内文件列表、公共库文件正文页、公共库下载或实际问答跳转。现有目录也没有公共库的新建、编辑、删除、上传管理入口。
- 涉密列表遵循全站共享组件 `src/secret-file-list.js` 和 `secret-file-list.css`。百舸文库后台的文件清单是另一套业务页面，保留其字段、流转和权限管理。当前代码没有把知识库目录或个人文档与文库后台文件数据同步。

### 2.3 搜索和筛选

1. 关键词表单以「搜索」或回车提交，去除前后空格、大小写不敏感，采用连续子串匹配。公共库匹配名称、创建人、简介、企业或部门名；个人文档匹配文件名称和文档类型。该搜索不读文件正文，也不查询文库后台文件记录。
2. 范围默认「当前分类」，企业或部门的当前分类搜索继续遵守所选组织。选「全部分类」并有关键词时，搜索跨越行业、企业、部门及个人，同时忽略企业及部门的原组筛选。结果先展示公共库卡片，再展示命中的个人文档表。无关键词时仍显示当前分类的常规内容。
3. 只有个人页签显示文件类型筛选，枚举为文档、表格、演示、图片、其他。筛选只影响个人记录，公共库结果不受该条件影响。文件类型是演示的可编辑分类字段，和扩展名或 MIME 校验属于不同概念。
4. 搜索不会改动分类页签的选中状态和原始计数，结果数另显示。切换分类会清除关键词并回到第 1 页；切换搜索范围、提交搜索、切换文件类型或个人分页大小时回到第 1 页。各分类筛选状态和分组折叠在当前实例内保留。
5. 非空关键词下提供「清除搜索」并回到当前分类视图，保留其筛选条件；常规无匹配时提供「清空筛选」，可同时恢复默认搜索范围、全部组织、全部类型、展开分组和第 1 页。个人表默认每页 10 条，可切换为 20 或 50，支持上一页、页码及下一页。
6. 页签可用方向键及 Home / End 切换，分组支持键盘展开和折叠。弹窗操作完成后归还焦点到文件名或搜索框。

### 2.4 个人文档字段与操作

- 前台表格字段固定为「文件名、上传时间、文档状态、操作」。状态旁的眼睛查看涉密审查详情。操作区为查看文件、下载、删除图标。时间单元格显示到分钟，完整时间保留在悬浮提示。
- 当前页面数据是 `src/pages/knowledge.js` 中页面内存初始化的 `personalDocs`，包含 `id / name / type / created / status`。两条种子如下。它们没有文件正文、原始文件、所属账号、文库记录关联、检测时间、审核节点、操作人和审核意见等真实记录。

| 个人文档 ID | 文件名 | 类型 | 上传时间（种子数据） | 状态 |
| --- | --- | --- | --- | --- |
| `personal-writing` | 专业写作专用 | 文档 | 2026-09-24 18:03:04 | `passed` · 已通过 |
| `personal-sensitive` | 敏感词导入模板 | 文档 | 2026-10-15 10:05:30 | `hit` · 涉密可疑 |

- 文件名可点击打开编辑表单，预填名称和类型。名称需去除首尾空白后非空，输入控件最多 80 字符；类型使用前述枚举。保存修改名称与类型，保留 ID、上传时间和状态，重新算搜索结果与分页；取消或关闭保留原值。当前不校验重复名称，不更改实际资源。
- 所有有记录的行可查看涉密详情，包括未通过的文件。详情仅展示文件名、状态和演示提示。没有在前台本页发起人工审核、指定审核人、通过、驳回或重新检测的流程。
- 只有 `passed / approved / stored` 可以打开「查看文件」。当前打开后明确显示「文档正文待接入」，未绑定真实预览；涉密可疑及其他不允许状态在按钮及事件处理两处拦截。
- **当前下载均禁用。** 通过状态提示「原文件未接入，暂不可下载」；其他状态提示「通过涉密审查后可下载」。只有审核通过、且原件可用的下载条件是共享列表设计约定，本页没有已连接原件的实现。
- 删除先弹确认，展示文件名。确认后从当前页面内存数组移除，并重算数量、搜索结果和分页；取消无变更。当前没有永久删除、回收站、软删除或后台联动。
- **当前没有新增或上传入口。** 「管理个人上传文档」描述业务用途，不能据此认为已实现真实上传、格式/大小限制、自动涉密检测或入库。编辑和删除只在当前页面实例有效，完整刷新后回到种子数据。当前数据未按账号隔离，也没有数据库或浏览器持久化。

### 2.5 共用涉密状态与权限边界

| 共用状态编码 | 共享列表显示 | 个人文档是否允许打开正文入口 |
| --- | --- | --- |
| `detecting` | 检测中 | 否 |
| `passed` | 已通过 | 是 |
| `hit` | 涉密可疑 | 否 |
| `submitted` | 审核中 | 否 |
| `approved` | 审核通过 | 是 |
| `stored` | 已入库 | 是 |
| `rejected` | 已驳回 | 否 |
| `failed` | 失败 | 否 |
| `draft` | — | 否 |

未识别的状态在公共组件中回落为「失败」，且禁止查看正文。上表是共享状态、文案和查看条件，不代表知识库个人页实现了状态之间的迁移。普通个人资料元数据操作与涉密正文访问使用不同条件，当前编辑和删除不依赖 `canView`。

### 2.6 入口权限和部门数据申请

- 控制台会检查整页的「知识库」功能权限。知识库页面自身没有按单库访问权限过滤目录或拦截库卡片；组织分组用于导航和筛选。入口权限与三元角色的关系见第 5 节。
- 个人中心「权限申请」中可把功能权限与部门知识库数据权限放在一张申请单中，部门数据可跨组多选，至少需要一个申请项和申请事由。新建数据申请只列出 `knowledgeDirectory.departmentGroups` 的 8 个库，按部门分组；历史种子数据含企业和行业等范围的演示申请，不能据此把企业库视为当前可新申请。
- 数据项键为 `d:<知识库 ID>`，并保留 `type: "data"`、显示名、`kbId`、`scope`、逐项状态。功能项用 `f:<route>:<child>` 区分。审核员可在旧有「权限审核」按项通过或驳回，历史保留申请人、申请事由、提交及审核时间、审核意见、申请项及各自结果。申请结果具有待审核、已通过、部分通过、已驳回。
- 浏览器持久化键为 `baige.permission.requests.v1` 与 `baige.permission.grants.v1`。只有审批通过的**功能项**被写入功能路由授权；审批通过的**数据项**保留在申请单及详情，目前不形成公共库读取 ACL、可下载 ACL 或问答检索 ACL。个人中心「当前人员」用于模拟申请人与查看该人记录，区别于控制台的 IAM 账号切换。文件涉密审核、知识库数据权限审批和 IAM 角色变更审批是三种不同的检查，任一项通过都不能代替另两项。

### 2.7 知识问答关系及旧来源目录

- 控制台首页「知识库问答」和百舸问答「知识问答」使用 `BaigeData.knowledgeBases` 八个兼容来源，浮动助手的知识问答选择也读取该数据。选择器有行业、企业、部门范围，可按名称搜索、跨范围多选，确认后生效，取消回到之前已确认的选择。知识问答发送需至少选择一个来源；个人文档不在选择器内。
- 首页控制台内提交问题可由壳层转发到百舸问答的「对话」入口，并把问题与合法的知识库 ID 一次性传入。交接消息带校验和去重，问题和来源不拼接到 URL。进入对话后历史会将选用的来源 ID 与会话保存在浏览器 `baige.qa.history.v1`；只识别兼容目录里的 ID，老会话无有效来源时提示重选。
- 问答回复、引用、原文面板均为演示。原文交互示例能打开引用页码并高亮段落，不证明真实内容读取或检索接通。公共库卡片的数据源未直接接这个选择器；目录和问答来源除兼容标识外无权威映射。当前独立问答页不在原型交付范围。

### 2.8 与数据摆渡对接前需确认

- 数据摆渡是否与公共库级、组织级、单文件级操作关联。当前页面没有公开文件对象及其目录归属可供复用，不能把一个库卡片默认为一个待摆渡文件。
- 生产环境的知识库 ID、企业/部门 ID、用户 ID、文档 ID 和文件版本 ID 如何定义，以及历史问答来源 ID 是否映射到这些对象。显示名称可能重名或改名，创建人和时间只是展示信息。
- 数据权限是否对目录可见、文档预览、下载、检索和摆渡申请分别控制。需要明确生产环境的授权主体、组织边界和逐动作判定。现有功能授权与部门数据审批事实分开使用。
- 涉密状态需要和来源环境、接口凭证、文件正文是否可用、文件版本及确认的审批记录一起判定。不能把通用界面状态徽标或本地演示记录当成真实放行凭据。
- 个人文档是否是摆渡来源或目的地以及它的生命周期，需要由新需求明确决定。上传入口、真实存储、账号隔离、正文预览、原件下载、删除后的审计都需要独立定义。

### 2.9 客户端基线验收与定位

1. 打开知识库默认显示行业四卡；企业与部门按组织展示，数量分别为 5 和 8。
2. 部门搜索「HR」可命中 HR 部四条，例如 `ces` 和「测试0930」，不包含新闻部测试；范围切到全部可跨企业、部门命中，个人类型条件不删除公共库结果。
3. 点击行业文献库出现待接入文案。公共卡片搜索结果保留相同动作和标识，选取后不会误开文库后台或假装有真实问答结果。
4. 个人「涉密可疑」可打开涉密详情，正文操作不可用；「已通过」可打开演示正文弹窗，下载仍禁用。确认删除或保存后，当前页面立即更新；刷新可恢复种子数据。
5. 首页/问答知识选择器仍可找到八个旧来源，部门权限申请仍用独立的目录 ID，不能通过任何一个入口推断真实检索已接入。

## 3. 客户端百舸文库

### 3.1 入口和文档范围

- 导航路由为 `library`，页面 [pages/library.html](../pages/library.html)。左侧只有「百舸文库」一级入口，路由保留「文库首页」内部标识，用户端导航没有文件管理或权限管理子入口。后台从平台后管系统另进。
- 前台载入时从 `BaigeLibraryStore.loadDocs()` 取文档，映射为标题、分类、机构、日期、热度、作者、文献类型、摘要、权限与归属元数据。与后台文库共享文档数据；不会读入前台知识库目录或个人文档。初始文库内容配置含 8 个分类、24 篇文库演示文章和 6 页共享预览示例，清空原型存储首次加载时，会把 24 篇文库样例、40 篇权限样例和 3 篇文件样例合并并按标题去重。当前种子实际生成 67 篇，其中 52 篇爬虫来源、15 篇部门上传，57 篇全部公开、10 篇有限公开。
- 当前候选集只保留涉密状态 `passed`、`approved`、`stored`，并排除解析状态 `failed`。这不等于校验已完全解析：例如 `passed + parsing` 可进入候选集。前台在脚本初始化时构造该列表，请按刷新后读取结果来理解原型；没有接入持续发布或检索索引更新。
- 原型可在前台切换「当前部门」和本部门「当前人员」，用于演示有效权限。部门、人员选择分别记在 `baige.library.dept.v1`、`baige.library.user.v1`；切部门时人员选项换成本部门，原先人员不适用时选择该部门第一人，关闭阅读并回到首页。前台阅读身份和后台管理部门选择独立。

### 3.2 首页、分类、搜索和分页

- 入口展示「全部」和八类文档，依次为智库成果、船舶标准、行业专利、三方研报、规则规范、专业书籍、期刊论文、其他。八个类型对应后台文档归属管理规则。初始推荐区为「智库成果／热门」，每种分类最多显示 6 个首页卡片。
- 「热门」按热度降序，「最新」按文档日期降序。查看更多展开对应分类的全量列表。卡片展示类型封面、标题、文献类型、日期和当前人访问提示，支持点开阅读。空分类提供返回全部的入口。
- 顶部按文档分类限定查询，默认「全部」。普通检索按标题、分类、机构、作者、文献类型拼接后做不区分大小写的包含匹配。空关键词返回首页并提示。检索结果展示关键词、分类和命中数，无结果时提示更换关键词。
- 顶部「AI 语义检索」是本地演示：完整问题命中标题加分，按空白和标点拆出长度大于 1 的词，再按标题、分类、摘要、日期打分，展示分数大于 0 的文档。没有向量检索、AI 接口、正文索引或跨库搜索。
- 结果页和更多列表各有分页，默认每页 12，可选 12／24／48。切每页数量时回第一页。阅读工作区的侧边搜索默认每页 8，可选 8／16／24，按标题、机构、作者或分类查找；工作区的「AI」按钮目前提示后调用同一关键字搜索，和首页演示排序不同。

### 3.3 阅读工作区、单文档问答和下载

- 卡片进入工作区。左侧是可收起的文档搜索和结果，中间是当前文档的元信息与预览，右侧是可展开、收起和拖动宽度的单文档问答。可从搜索打开多个文档，顶栏用页签切换和关闭，空间不足时从已打开列表进入，关闭最后一个页签退出阅读。
- 预览头部显示标题、文档分类、收录日期和访问提示。全文权限下展示 6 页演示正文，其余情况当前代码展示前 2 页和试读结束提示。预览使用一套共享示例内容，单篇标题、作者和日期替换在第一页，没有接入每份文件的原文或分页清单。
- 单文档问答须有全文权限。问题提交后出现加载提示，按关键词返回演示答案，出处按钮滚到对应示例页。历史面板按当前打开文档展示预置问题和本次会话追加的答复，当前页签内存保存；输入、答案和出处没有接到真实知识库或模型。
- 下载依赖归属本部门或生效权限为 4。无权给出文案；有权仅显示开始下载和记录日志的提示，实际没有输出原件，也没有可验证的后台下载流水。「有限公开」文案中的付费提示没有支付流程；正式取得全文和下载靠对象授权。
- 后台文库上传与前台文库浏览共享的是统一文档记录。没有把上传文件二进制、解析文本、引用定位或下载审计联动起来。

### 3.4 访问控制应遵循的语义与原型差异

- 业务要求中，0 为无权限，1 为只允许检索命中元信息，2 可在列表／详情查看元数据，3 可全文在线阅读（有限公开时仍只试读），4 可全文和下载。归属部门有全部权限，外部门按公开模式与授予对象计算，详见后台授权一节。
- **当前缺口**：展示层在列表和搜索中未按 0／1／2 过滤，低权限文档仍可能出现卡片；阅读函数只区分是否有全文权限，可能给 0／1／2 展示两页演示正文。这个行为与访问级别语义有差异。单文档问答发送做了全文判断，但历史面板仍可显示脚本预置的示例答复。摆渡后的真实内容需要按各操作的权限拦截，不能沿用这些演示放行。
- **当前缺口**：阅读页将共享文档转换成自己的视图数据时，保留权限等级和到期时间，但漏传 `publicDept`、`publicPerson`。因此后台已为有限公开文档配置了目标级「全部公开」时，数据层会计算出 4 级，现有阅读页却可能仍将外部门用户显示为试读，无法得到应有的全文和下载入口。按照正式授权语义验收时要覆盖这一条。
- 当前预览、检索、授权读写和模拟身份都在客户端。若生产端正式提供封面、缩略图、摘要、试读、原文、搜索命中或 AI 引用，它们应按各自的授权范围返回；某个 UI 隐藏操作无法证明对应数据没有被读取。

实现定位：[用户端页面](../pages/library.html)、[文库浏览与阅读控制器](../src/pages/library.js)、[文库演示数据与预览正文](../src/library-data.js)、[文库共享数据层](../src/library-store.js)。

## 4. 后台百舸文库（文件管理与权限管理）

> 已核对当前工作区的 [后台页面及页内控制器](../pages/library-admin.html)、[共享文库数据层](../src/library-store.js)、[演示数据](../src/library-data.js)、[视觉与业务约定](../DESIGN.md)。本章分别标注界面所表达的业务规则、原型实际完成的链路和未接通的部分。三个相近概念要分别对待：文档归谁管理、文档通过了哪道检查、某个目标现在能怎么使用该文档。

### 4.1 入口、角色与管理边界

- 由 [后台壳](../admin.html) 的「百舸文库」组进入「文件管理」「权限管理」。对应后台地址 `admin.html#files`、`admin.html#perm`，分别加载 `pages/library-admin.html?embed=admin&view=files` 和 `?embed=admin&view=perm`。独立打开管理页默认进文件管理，`?view=perm` 或 `#权限管理` 可打开权限管理。独立页可返回前台「文库首页」。
- 文件管理是后台常用入口，打开后直接到当前部门的百舸文库文件列表。页内保留了旧知识库选择和审批演示代码，后台常规入口以 `#libPanel-upload` 和 `#libPanel-perm` 为准。
- 顶部「当前部门」是模拟管理视角；数据层 `getManageDept/setManageDept` 单独保存当前管理部门。前台读者模拟使用另一组当前部门和当前人员，切换后台管理部门不等同于切换读者身份、登录人或三元权限的演示身份。在未选过管理部门时，前台当前部门若属于四个管理部门则用它作默认，否则回落至经研中心。
- 组织有六个部门可作为文档授权对象：经济研究中心、动力研究院、技术经济中心、船级社规范所、国际航运研究中心、情报研究所。每部门有演示人员，授权目标可按组织和人员查找。四个管理部门参与分工，其余两个可作为授权目标。

| 管理视角 | 对应组织部门 | 负责文档分类 |
| --- | --- | --- |
| 经研中心 | 经济研究中心 | 智库成果、三方研报 |
| 标准中心 | 船级社规范所 | 船舶标准 |
| 知产中心 | 技术经济中心 | 行业专利 |
| 数智中心 | 情报研究所 | 规则规范、专业书籍、期刊论文、其他 |

- 文件管理按 `source = upload`、`ownerDept = 当前管理部门`、分类在部门职责内筛选。爬虫平台采集的文档不会进入部门上传列表；单条和批量删除再次校验 `canManageDoc`。
- 权限管理按当前管理部门负责的分类和归属筛选，同时包含 **部门上传** 与 **爬虫平台** 两种来源。来源与管理归属独立，例如某标准虽然来自爬虫平台，也应在标准中心权限管理中出现。
- 数据层规整文档时根据 `category` 映射 `ownerDept`，未知分类归入「其他」，并保持归属部门完整权限。来源 `source = upload | crawl`，展示名「部门上传」以及「爬虫公开／爬虫平台」；不同页面的爬虫来源显示称呼有差异，跨系统对接应使用来源代码核验，避免把显示文案当成字典主键。管理归属字段也不能代替实际上传者或原始采集机构。
- 功能导航、百舸文库的文档级授权、文件涉密审核是不同对象。三元权限「角色授权审核」处理账号、角色和菜单；后台另一个「权限审核」处理个人申请的功能与部门知识库数据项；百舸文库「权限管理」直接配置文档授权。当前原型无证据表明三者通过一个申请流统一写入。

### 4.2 文件管理列表与操作

- 列表为 10 列：勾选、文件名（文件类型图标）、文件来源、文档类型、版本号、创建时间、解析状态、涉密审查状态、最近更新、操作。涉密可疑、审核中、已驳回时在状态旁通过小眼睛打开「涉密检测详情」。
- 组合筛选包含开始与结束日期、解析状态、涉密审查状态、文件名。文件名大小写不敏感地做包含匹配，起止日期按日比较且含边界。点「查询」回到第一页；空态提示从「上传文件」录入。每页默认 10 条，可切换 24、48 条，显示结果总量、当前页和页码。
- 可勾选当前页可见文件后执行批量删除，单条删除与批量删除实际从共享文档记录中移除。批量删除按列表 DOM 中的当前勾选项取 ID，不能视作跨页选中；表头方框目前只切换自身显示，没有把当前页全部行置为选中。资产级历史、软删、保留期限或删除回写由后续正式业务规则定义。
- 通常操作区显示预览、下载、刷新状态、编辑、删除。涉密可疑、审核中和已驳回的行以「—」代替普通操作；检测中的行当前仍可能绘制普通图标，但此界面的原件下载、普通正文预览、编辑均仅提示待接入，刷新只重新绘制列表。审核详情内「查看文档详情」使用预置样例，不能当作未批准文件的真实原文可读授权。
- 文档列表当前把创建时间和更新都映射到 `date`，未用数据层已有的 `uploadedAt`、`updatedAt`。动作除批量删除外部分以文件名查找首条记录；同名文档存在歧义。数据摆渡需求另定稳定文件标识、版本标识和时间含义，禁止只按此处展示名认定同一文档。

### 4.3 三步上传与文件信息

1. **上传文件**：通过「上传文件」打开三步向导。界面写明拖放或点击、Word/PDF、单文件 ≤ 50 MB。当前上传区点击只插入三条固定演示文件并模拟上传进度，没有真实文件选择、格式/大小校验或服务器上传。添加样例即可进入下一步，代码未等待所有上传进度完成。
2. **补充信息**：左侧显示文件、文件数和大小合计，可逐项切换；右侧对被选文件显示封面、可编辑文件名、只读文件类型与大小、可编辑版本号（默认 `V1.0.0`）、只读管理部门。封面可通过六种预设、自定义图片入口或 PDF 首页自动获取，后两项仍是模拟。界面标记封面必填，当前下一步校验的是当前选中文件有封面，未逐个校验批次内所有文件。文档分类必选，只展示管理部门的职责分类，只能选一个；标准中心和知产中心这类只有一种分类时自动选好并锁定。公开方式默认「全部公开」，也可选「有限公开」。当前向导中的公开方式和文档分类是整批设置，切换文件不会生成每文件独立设置。
3. **完成录入**：显示待录入数量及涉密检测须知，确认后显示短暂录入中提示，再关闭并在列表增加记录，逐条异步检测。实际持久化文件标题、分类、来源、归属、公开方式、组织、作者、日期、文件类型、版本默认值、初始状态、摘要、关键词等元数据。向导实际写入 `version = V1.0.0`，用户修改的版本及封面、文件大小、文件二进制未按向导内容落库。预期元数据完整性需要独立验收。

- 「全部公开」作为文档默认公开方式，非归属部门默认可在线阅读全文，默认不可下载；并非授予所有人下载。「有限公开」下归属部门可阅读全文及下载，未获额外授权的其他部门在原型默认可试读前两页。界面曾把有限公开称为「付费文档」，未见订单、支付或结算能力。
- 默认来源字段由现代文库统一记录。旧页面的企业、部门和个人 `KB_DATA` 演示集合只是遗留视图的数据，不是当前后台百舸文库的目标库或公共知识库目录。

### 4.4 涉密检查与解析状态

文件同时有两条独立的状态轴，不能混用。后台保留自己的涉密标签，与个人知识库等前台工具共用列表的八状态不同。

| 状态轴 | 枚举 | 界面标签或含义 |
| --- | --- | --- |
| 涉密 `secretStatus` | `detecting` | 检测中，录入后进入自动检查 |
| 涉密 `secretStatus` | `passed` | 已通过，后台同一值表示演示机器通过，旧审批示范也用它表示人工通过 |
| 涉密 `secretStatus` | `hit` | 涉密可疑，待上传方决定是否继续并提交人工审核 |
| 涉密 `secretStatus` | `submitted` | 审核中，等待管理员处理 |
| 涉密 `secretStatus` | `rejected` | 已驳回，不进入解析；详情有「重新上传」入口占位 |
| 解析 `parseStatus` | `unparsed` | 未解析，前置检查未通过或尚未开始 |
| 解析 `parseStatus` | `parsing` | 解析中 |
| 解析 `parseStatus` | `parsed` | 已解析 |
| 解析 `parseStatus` | `failed` | 解析失败，可以筛选；三步向导演示没有新生成失败分支 |

- **自动放行分支**：录入后初始 `detecting + unparsed`，演示定时器根据固定样例的预置标记设为 `passed + parsing`，再设为 `passed + parsed`。
- **可疑分支**：录入后设为 `hit + unparsed`，记录演示关键词与命中片段。涉密详情会显示文件名、版本、解析策略、创建时间、解析/审查状态、命中关键词、流程记录，并提供「取消上传」和「继续上传并提交审批」。取消删除当前记录；继续将共享存储的状态改为 `submitted`。审核中只给关闭按钮；驳回态入口提示重新上传尚待开放。
- **人工审批的界面意图**：上传者发送后由管理员审查并给出通过或驳回，驳回需原因，通过后进入解析。这套完整业务链路 **在当前后台尚未接通**。旧的同页审核中心与审核管理使用各自 `KB_DATA` 的示例队列和按文件名查找的处理逻辑，真实入口的 `continueSecretUpload` 只更新现代文库记录，不创建旧队列事项，旧审核回写也不会完成这条共享文档的闭环。不得把点击「继续上传并提交审批」视为审核已经完成。
- 浏览器定时器只是上传和检查的演示。当前没有跨刷新恢复、可查询的服务端检测任务、真实解析、入库发布事件或可靠任务重试机制，检测过程中刷新可留下中间态。权限管理列表按管理范围读记录，没有统一先过滤涉密/解析状态；前台读取另有过滤（详见前台文库章节）。迁移时若要记录历史审核结论，须使用获确认的结果和审查记录，不能从「已录入」、授权值或「解析相关字段」推导放行。

### 4.5 权限管理页面与授权对象

- 使用左侧授权对象树选择部门整体，或展开后选择单人；可搜索部门与人员。当前管理部门及其人员不在可选目标树里，因为文档归属部门已拥有完整权限。当前未选对象时给出选择提示。切换授权对象时回到第一页并清空已选记录。
- 上方有文档检索（标题、发布机构、作者、分类、日期均参与包含匹配），来源（全部文档、部门上传、爬虫平台）、职责范围内分类、公开方式（全部、全部公开、有限公开）筛选。空搜索会提示输入；清空搜索恢复。界面代码虽留有 `aiMode` 文案变量，此后台检索入口实际运行普通过滤。
- 文档权限表显示选择框、文档名、公开方式、发布机构/作者/时间、来源、文档分类、当前权限、操作。无权限显示「没有权限」，有权限按等级、两页试读、对该目标全部公开、有效期等信息展示。个人视角显示「部门基础」「个人加授」和「生效」三个值。
- 分页默认 12 条，可选 24、48 条。表头只全选当前页；选中 ID 由集合保留，可跨页。界面显示当前筛选范围总量、未额外授权/已调整的演示计数、已选数量。文档有单条「授权／调整权限」；批量「赋予所选」作用于勾选集合，「赋予当前筛选全部」覆盖该次筛选的所有页，「全部设为默认／清除全部个人加授」覆盖当前管理部门负责的完整文档范围。
- 树中企业节点可被选中并显示「船舶研究院（企业，全部部门）」，但当前代码只以字符串 `enterprise` 作为单个授权目标写入，没有展开六个部门、也没有定义前台身份继承该项的逻辑。因此企业全域广播授权 **不是已实现行为**，摆渡不能沿用这个节点的文字推断面向所有部门的 ACL。

### 4.6 授权等级、公开方式、有效期

| 等级 | 主要含义 | 说明 |
| --- | --- | --- |
| 0 | 部门无权 / 个人无额外授权 | 对部门为显式收回。对个人回到部门基础，不能用来剥夺继承权限 |
| 1 | 可搜索 | 通过搜索命中标题、摘要等元信息 |
| 2 | 可见 | 可浏览列表与详情元数据，但不解锁全文 |
| 3 | 可在线查看 | 已有较低级能力。对普通全部公开文档可在线阅读全文但不可下载；有限公开的非归属目标继续受试读限制 |
| 4 | 可下载 | 具有低等级能力及阅读全文、下载。有限公开的非归属目标要通过单独的「全部公开」授权模式获得该能力 |

- 等级包含：高等级自动包含低等级。部门基础权限与个人加授的有效值取最大；单独给个人的权限只可提高部门结果。对于一个人同时设置多篇文档，显示支持的等级须高于所选文档中的最高部门基础值；数据层再次拒绝无意义的低级正值加授。
- 整篇文档的 `accessMode = public | limited` 是发布方式。有限公开文档需要为某个部门/人员解锁全文及下载时，页面在所选文档**全为有限公开**时提供「有限公开（试读）」与「全部公开」两种目标授权方式，分别走等级 0–3 或目标级公开标记 + 等级 4。目标级「全部公开」只改变选中对象，不修改整篇文档对其他部门或人员的发布方式。文档本身全部公开时仍可针对某个部门设 0–4，也可给个人合法加授。
- 对含全部公开与有限公开的混合批次，原型不显示目标级公开切换；存储层会把有限公开文档的普通数值等级限制在 3。个人加授级别 4 若含有限公开文档，存储层报错，因为必须走目标级全部公开。前后台映射和批量反馈不能把混合批次的四级选择简单解释为「所有选中文档已开放下载」。
- 永久有效、7 天、30 天、90 天、自定义截止日。自定义落在浏览器时区当日 23:59:59，验收提示显示到分钟；拒绝缺少日期和不晚于当前时间。等级 0 没有授权到期日。有效值读取时判断是否过期，同时后台每 30 秒尝试清理过期覆盖。个人过期后回到部门基础；部门过期清除单独覆盖与公开标记，回到文档默认规则（通常等级 3，有限公开回到试读）。不能笼统把「回收覆盖」理解成永久禁用、继续保留下载，或把渲染瞬时的 0 当作整个到期后的默认模型。
- 「不授权」与「恢复默认」含义不同。前者写入 0 并清除目标级公开，后者删除特定目标覆盖恢复文档初始规则；清除个人加授不会改动部门权限。读者是否能获取正文还要结合文档状态、发布方式、部门/人员有效授权以及真实文件是否存在。

### 4.7 数据对象、持久化和接口边界

- 共享 `BaigeLibraryStore` 当前用 `localStorage` 保存 `baige.library.docs.v4`，并在当前页面持有内存缓存；尝试迁移 `baige.library.docs.v3`，无有效数据时生成演示数据。旧版迁移会按责任分类重新归属、保留目标公开标记并把部分有限公开的旧零值恢复为默认试读。它是原型的兼容逻辑，不是保留正式授权历史的摆渡规则。
- 前台部门 `baige.library.dept.v1`、前台人员 `baige.library.user.v1`、管理部门 `baige.library.manage-dept.v1` 分开存放。写入触发 `baige:library-store` 事件；当前无服务端共享、跨端身份验证、数据库事务、文档级操作审计或外部传输接口。前台为加载时重建文档视图，不能依据存储事件假定已打开窗口实时同步。
- **文档本体**：`id`（当前按本地最大整数加一）、`title`、`category`、`source`、`sourceLabel`、`ownerDept`、`accessMode`、`org`、`author`、`date`、`uploadedAt`、`updatedAt`、`docType`（展示文档形态）、`fileType`（`pdf/doc`，与业务分类分开）、`version`、`strategy`、`abstract`、`hot`、`origin`。
- **流转和权限**：`parseStatus`、`secretStatus`、`kw`、`auditReason`、`permissions`（部门等级）、`permissionExpiry`（部门到期）、`personPermissions`、`personPermissionExpiry`、`publicDept`、`publicPerson`。命中片段 `hitPreview` 可在当前页用 `updateDoc` 写入，但不属于 `normalizeDoc` 字段，重新加载时不能保证保留。规范化对缺失状态使用 `parsed/passed`，只适用于兼容演示数据，不能充当生产导入默认放行策略。
- 当前没有真实文件的存储引用、原始大小、MIME、校验摘要、封面引用、处理任务 ID、独立审批记录或正式入库记录。即使存在本地记录、已解析标签和权限配置，也不能证明有可下载的原文件、真实解析结果、审核凭据或可迁移二进制资产。

### 4.8 后台回归验收要点及代码索引

1. 经研中心能在文件管理看到本部门已上传的智库成果和三方研报，看不到爬虫文档、船舶标准或其他部门文件。进入权限管理仍能看到经研中心负责的爬虫文档，切换来源后结果正确；切换标准中心仅出现船舶标准。
2. 上传向导部门单一分类自动填、其他部门在职责内单选；分类与公开方式分别落到 `category` 和 `accessMode`。演示检测权责与已接通的文件状态按 4.4 验收，人工审批闭环另记为欠缺。
3. 同一有限公开文档给单人设全部公开后，数据层应算出 4 级；同部门其他人员仍依各自权限计算，取消个人加授时该人回到继承权限。全文和下载是该授权的业务目标，现有阅读端存在第 3.4 节所述字段遗漏，端到端验收时需补齐。有限公开普通等级不会直接解锁下载，全部公开的部门默认在线阅读也不会自动变成可下载。
4. 显式部门等级 0、恢复默认、到期清理、仅对部门或单人临时解锁等用例结果不同。权限变更不能跨错管理部门、跨错文件版本或改变其他目标；风险边界须由服务端实现。现有测试锁定样例数据、归属范围、个人加授、目标级公开、恢复默认和 V3 兼容。
5. 当前行为可查 [后台 UI 合同测试](../tests/library-admin.test.cjs)、[文库数据层测试](../tests/library-store.test.cjs)、[文库演示资源测试](../tests/library-data.test.cjs)。真实文件、人工审批和数据摆渡接口属于后续工作，不能把这些演示测试计作其验收。

## 5. 权限与问答的边界

### 5.1 分开识别四条业务链

1. **功能入口权限**决定某个账号能否打开「知识库」「百舸文库」「百舸问答」等页面。角色授权审批改变的是用户与角色的关系、账号或角色状态、角色内菜单，作用于控制台入口。
2. **个人权限申请**包含功能项和部门知识库数据项。功能项通过后生成入口授权。部门知识库数据项通过后展示审核结果，当前原型没有把它写成可执行的数据访问规则。
3. **百舸文库文档授权**决定文库的某篇文档对指定部门或人员可搜索、可见、可在线查看或可下载的权限级别。它与文档的归属管理部门、发布模式、授权期限有关，存放在文库自己的文件记录上。
4. **涉密核查及人工审查**决定文件能否进入业务可用范围，属于文件状态链。文库授权、用户角色审批、部门知识库数据申请均不能替代该状态。文库后台的审核预览供模拟核查人员使用，和前台文库正文访问的用途不同。

这四类信息应分别辨认。已有菜单授权只证明可以进入相应页面，不能直接证明能读某份文件。审核通过的部门知识库数据申请也没有自动赋予百舸文库文档权限。

### 5.2 控制台入口与角色授权

- **入口**：「知识与研究」下列出「知识库」和「百舸文库」。平台壳分别使用路由 `knowledge` 和 `library`。`library` 的「文库首页」是子路由兼容入口，侧栏不展示独立子项，角色菜单以 `library` 为授权项。问答对话属于 `qa:对话`，与两库的菜单分别授权。
- **平台默认演示账号**：基础访问规则默认允许知识库、百舸文库和百舸问答的对话入口。功能审批产生的授权以申请人邮箱和 `route:child` 组合匹配，叠加于这一默认模式。当前实际规则中，「智能问数」「智研通」默认未开通，不能据此推断两库入口默认关闭。
- **切换平台演示账号或做实时账号菜单预览**：个人中心可选正常状态的 IAM 演示用户，平台使用会话区键 `baige.iam.client-account` 或 `iam-account` 参数记录选择，`iam-user` 则是独立菜单预览参数。两种角色模式均基于 IAM 当前已生效的角色菜单，账号和角色必须正常。角色权限取正常角色的并集，客户端过滤 `review`、`system` 等后台保护菜单。正常账号保留首页入口，菜单与页面导航按实际授权拦截。角色模式不叠加个人权限申请的旧授权路径，个人权限申请脚本在角色模式下不初始化。角色变化后，壳会重算导航，并清理已打开但当前账号不再能访问的模块。
- **IAM 审批入口**：后管端「用户管理」「角色管理」发起，二者共用「我的申请」抽屉。「角色授权审核」由独立审核员身份处理。新建用户必选角色，角色关系审批通过才正式生效。角色菜单、启用/停用、删除待审时暂不接受新增该角色，已有新增申请暂缓通过。撤回、驳回与失效的记录不等同生效授权。零正式成员角色只改菜单有直接保存的特例。上述审批属于角色生命周期，不会同步写入某篇文档的权限字段。
- 原型内置角色名称包含「行业库涉密审核员」「企业库涉密审核员」「百舸库涉密审核员」「行业知识库上传」「行业知识库审核」。当前记录里的两库项以菜单授权为主，相关角色名称本身没有绑定百舸文库后台的部门切换、前台文库模拟人员、知识库个人文档上传或涉密核查操作。文库管理页面由后台演示身份和单独的文库管理部门切换器演示，不能把名称相似的角色当作生产操作鉴权依据。
- 角色数据为浏览器原型。用户、角色、用户角色申请、事件在 `baige.iam.v1`，后台演示审批身份在 `baige.iam.actor.v1` 会话区。权限预览、平台演示切换和后台审批切换解决的是三个演示场景。

### 5.3 个人权限申请及其实际生效范围

- **申请入口**：「个人中心 → 权限申请」，默认停在「我的申请」，点击「申请权限」打开表单。默认模式下，从首页未开通功能进入申请时可预选相应功能。弹窗「当前人员」切换的是发起和查看申请的模拟视角，按申请人邮箱读取记录，切换时清除草稿选择和事由，不改变控制台账号或文库阅读部门。
- **申请内容**：功能目录来自平台功能配置，按首页分类分组。「已开通」和「审核中」的功能项不可再次勾选，允许勾选多项。数据项从 `knowledgeDirectory.departmentGroups` 产生，按售后部、HR部、714部门2、新闻部分组，可跨组多选。新申请表单只列部门知识库，行业库、企业库、个人文档、百舸文库文档均不在此数据申请范围。数据项当前没有与功能项相同的过往申请禁选检查。申请须至少选择一个功能或数据项，事由必填，输入上限 500 字。
- **申请数据**：`AP + YYYYMMDD + 三位流水` 标识申请，保存申请人快照、时间、事由、申请项、审批人、结果、意见和审核时间。功能项关键字段为 `type: function`、`key: f:<route>:<child>`、`route`、`child`、名称。数据项为 `type: data`、`key: d:<kbId>`、知识库 ID、名称和 `scope`，当前新单的 `scope` 为「部门」，表单上的部门分组标识不会另存进申请项。内置历史示例还包含行业、企业项，复核时按原记录展示，不能倒推仍开放相同的申请入口。
- **审批和结果**：后管端单独的「权限 → 权限审核」处理功能与数据申请，区别于「角色授权审核」与「百舸文库 → 权限管理」。可按申请人、功能或数据名、状态筛选。详情拆功能、数据两块，数据再按 `scope` 分组。审核员逐项选择通过或驳回，也可整单批量设置、按数据组批量设置。提交时全部申请项必须有处理结果，意见必填。结果为待审核、已通过、部分通过、已驳回。申请人在「我的申请」筛选查看，也可打开详情核对逐项结果。
- **本地持久化**：`baige.permission.requests.v1` 保存申请明细，`baige.permission.grants.v1` 只从已通过的 `function` 项派生按邮箱记录的入口授权，`baige.permission.viewer` 只保存弹窗模拟视角。部门知识库数据项仅在请求和审核结果中留痕。知识库目录、问答知识库选择器和文库 ACL 均没有读取已批准的数据申请来限制或开放访问。表单的「已认证」是演示文案。

### 5.4 百舸文库文档授权与组织身份

- **管理侧与使用侧分别切换**：后台「当前部门」用于选择四个文库管理部门，以负责的文档类型和文档归属决定可管理范围。后台「权限管理」左侧的部门和人员是接收文档权限的对象，来自六个组织部门及其演示人员，当前管理部门及其人员从可选目标中隐藏。客户端文库页的「当前部门／当前人员」负责演示以哪个主体阅读，和控制台登录者、个人申请弹窗模拟人员、后台审批人分别维护。文库人员有独立的原型 ID，后台组织树和知识库部门卡片也各有自己的标识，同名标签不能当作已有的映射表。
- **授权单位与计算**：文库按「文档 × 部门/人员」存储权限、目标公开标识、到期时间。等级 0/1/2/3/4 分别表示无权限、可搜索、可见、可在线查看、可下载。0 级作为个人设置时表示无额外权限。所属管理部门始终为 4。生效权限为部门基础与个人加授的较高值，因此个人权限不能用来削减部门授权。普通个人授权必须高于部门基础。对有限公开文档特别设定「全部公开」时只影响所选部门或人员，其他主体原有模式继续有效。有限公开的普通授权最高为 3，普通部门/人员默认仍是试读策略，外部门的全文、下载须有针对该主体的特别公开授权。期限到时失效，删除个人加授后仍按部门基础判断。未配置的外部门在原型数据层可回落至 3，真实系统是否默认开放需另行确认。
- **前后台联动**：后台文件管理和权限管理与客户端文库读取同一 `BaigeLibraryStore`。本地键为 `baige.library.docs.v4`（兼容 `v3` 旧文档）、`baige.library.dept.v1`、`baige.library.user.v1`、`baige.library.manage-dept.v1`。前台初始化时取快照，候选文档经涉密状态及解析失败条件过滤。后台写入后重新加载前台能重新取数，当前文库客户端没有订阅跨窗口实时变更。原型通过有限公开试读分支与全文分支展示正文，只有全文权限开放单文档问答。具备下载权限时目前仅提示开始下载，未接真实原件与可查的审计日志。
- **需要与现有模型分开核对的实现差异**：前台热门、分类列表、检索和阅读器侧栏目前从涉密状态允许查看且解析未标为失败的文档池中取数，没有按 0/1/2 将可搜索、可见严格落实到各场景。打开详情没有再拒绝 0/1/2，未达到全文条件时直接渲染样例前两页。另一个差异是页面创建文档展示对象时保留了部门/个人等级及到期时间，但遗漏目标公开授权的 `publicDept`、`publicPerson`，因此存储层可以记录有限公开文档针对特定主体的全文与下载授权，阅读器端的判断不一定能识别。现有实现只能作为原型行为记录，摆渡验收不能用这些前端表现替代访问规则。

### 5.5 两种问答与资料来源

- **百舸问答的知识问答**：首页提问、百舸问答「对话」和 AI 悬浮窗当前都可用三个范围的演示知识库，来源为 `BaigeData.knowledgeBases` 下八项。它和浏览页使用的 `knowledgeDirectory` 是两份数据，即使同一个字符串 ID 如 `industry-standard` 在两处出现，也有各自显示名称和上下文。未建立公共目录与演示问答来源的一对一映射。个人文档未加入知识问答来源，部门数据申请审批也不改变选择器可见项。
- 知识问答可跨行业、企业、部门分类多选，搜索按名称匹配。确认后使用当前选择，取消保留原选择。首页到对话从平台壳与模块之间一次性交付问题和来源 ID，校验目标是「百舸问答 → 对话」、问题最多 16000 字符、已传来源数组非空且最多 32 项，来源必须在演示目录内。此处的来源校验是输入校验。交付的问句和来源没有写进 URL 或导航历史。问答自身的本地会话历史 `baige.qa.history.v1` 可以保存问句和会话来源；悬浮窗另有 `qb-kbs` 保存所选范围。没有真实知识检索、文档解析关联、问答服务或实际引用回查。普通回复和引文原文为演示内容。
- **知识库目录的点库问答**：点击行业、企业或部门的库卡片会提示独立问答页面待接入。用户先做资料列表的决定已落实到原型，现在没有从真实库卡片进入库内文档或已连通问答的端到端流程。
- **百舸文库的单文档智能问答**：入口在文库阅读器内，围绕当前打开文档。具有全文访问权限才可输入和发送，切换文档重置当前问答视图，回复的示例出处可跳到正文对应页/章节。回答和预览使用共同的演示文本并按关键词选择回复，没有接文档真实字节或知识库引擎。阅读器历史按当前页面内的文档索引缓存，包含演示历史和本次问答记录，未绑定独立用户或服务端记录。它不会调用百舸问答的八项知识库选择器。
- **与数据摆渡的关系**：公共知识库目录元数据、库内未来真实文件、文库的文档数据和 ACL、问答选择器演示来源、申请与审批历史是不同实体。立项时需明确哪类对象进入摆渡、采用哪个稳定 ID 和哪边的主体映射。文档已经可检索、可引用、可试读、可下载、已通过审核这些状态，要各自用相应事实判断。

## 6. 数据摆渡立项时需明确的业务规则

这一节是下一轮需求访谈的起点，问题和建议验收场景尚未定为功能。先明确数据流向和目标对象，再讨论界面、权限、任务状态及接口。

### 6.1 优先确认范围

| 顺序 | 需要确认 | 为什么会影响已有业务 |
| --- | --- | --- |
| 1 | 源端与目标端各是什么环境、组织与系统，单向还是双向，谁启动、谁接收 | 区分「导到百舸文库」「迁到某个知识库」「两个环境之间交换」，它们的目标 ID、责任部门和权限边界不同 |
| 2 | 首期摆渡对象是文库文档、知识库及其文件、个人文档，还是其中几类；处理单件还是批量 | 只有文库有统一文档模型。知识库门户主要是目录，个人页也没有原件存储。不能用同一导入动作假定所有目标都可创建文件 |
| 3 | 可传哪些内容：原文件、元数据、封面、摘要、解析文本、索引、历史记录、授权及期限 | 这些数据可能要分别审批、重新生成或只记录摘要。明确必须、可选、禁止的字段；正式包和日志不应照搬浏览器演示对象 |
| 4 | 允许发起和接收的涉密、解析状态，在哪侧核查，目标侧是否复核，谁批准进入可读状态 | 当前原型的「通过」只是演示字段。导入成功、涉密通过、解析完成、对用户发布是不同事件 |
| 5 | 目标类型或知识库如何映射，归属部门和用户如何匹配，文档公开方式和对象级授权如何处理 | 文库按分类自动定归属，前台知识库按分类和组织布置。源端名称和本地角色 ID 不能自动作为目标端有效身份 |
| 6 | 目标已存在同 ID、同名、同内容或新版本时怎么处理；重试、补传、部分成功和撤销如何定义 | 目前文库以本地递增数字分配 ID，向导不提供通用跨系统去重。应明确源唯一标识与版本，避免重试产生重复文件 |
| 7 | 是否需要按既有发布渠道对索引、全文、试读、原件下载、问答引用、审计记录分别验收 | 业务访问权限和跨环境发布许可需分别落实。文档可读或可下载并不能推导出可摆渡 |
| 8 | 是否迁移删除、撤回、权限变更与审核记录；目标与源端后来发生变化如何处理 | 初次搬运与后续增量同步是不同范围。要先确定谁是权威源、目标端是否允许二次编辑 |

### 6.2 源端与目标端的对象映射

用以下分层划方案，具体字段、枚举、默认值和责任角色待下一轮确认。

| 映射层 | 源端要能说明 | 目标端要能说明 |
| --- | --- | --- |
| 内容主键 | 源系统、源环境、源对象类型、稳定源 ID、内容版本；有原件时可记录校验值 | 生成目标 ID 或关联既有对象，能按源 ID＋版本追查；文件改名不改变身份 |
| 归档位置 | 文库分类、源知识库 ID / 范围、组织归属等原始字段 | 映射到目标类型或库 ID；文库归属按目标责任规则校验；知识库目录 ID 与问答目录 ID 各自核对 |
| 内容与附件 | 原件、原文件名、类型、大小、封面、作者、机构、标题、日期、摘要；原件和衍生件分别识别 | 需要实际上传存储及可访问的版本引用；是否保留／重建封面、正文、索引和引用由目标端处理规则决定 |
| 可见性与授权 | 文档公开方式、对象授权、有效期限；记录实际来源，不用试读结果反推授权 | 默认和例外如何应用须由业务确认。未映射或已过期权限的处理应明确；不把源部门／个人名称直接当目标授权对象 |
| 审核、解析和发布 | 源端涉密判定、审批人／意见、时间、解析状态、删除状态等属于独立字段 | 原样留档还是触发新检测／新审批，均要明确定义。最终可检索、可见、可读、可下载和可问答的条件逐项落实 |
| 过程记录 | 发起人、时间、目的、原件清单及结果回执要求 | 需要记录任务结果、实际落库记录和失败原因；如需重新执行，应能识别是哪批哪条及对应版本 |

### 6.3 从原型沿用规则前要处理的数据差异

- 初始文库种子合并才按标题去重；新增文档分配本地数字 ID。后台部分行操作仍按文件名寻找记录。同名文件、不同版本和跨环境导入应以稳定对象 ID 和版本定位。
- 文库数据层会把未知类型归到「其他」，把非 `upload` 来源归到 `crawl`，把非 `limited` 公开方式归到 `public`。缺失的涉密状态和解析状态也会回填演示默认值。正式导入须明确哪些字段可以默认，哪些必须拒绝或留待人工处理，尤其不能让缺失的审查结果被解释为「已通过」。
- 当前文库导入前端不保存实际原文件、封面或解析结果。若摆渡需要传这些对象，应给每项资源独立引用和校验，避免记录已到而正文未到时仍开放。
- 文库文件管理显示的创建与更新时间当前由同一个文档日期字段派生。源文件日期、上传日期、申请和审核时间、目标接收时间、发布时间需要分别建模。
- 试读、全文、下载、问答和摆渡发起权应逐动作对齐。当前演示里的预览提示、历史样例、组名及浏览器选中的身份不能当成可传输的业务证据。

### 6.4 状态和回执建议讨论口径

- 为摆渡任务建立独立状态。可以讨论「待提交、处理中、部分成功、成功、失败、已取消」等候选，名称和流转以新需求确认结果为准。任务里的每条文档需有可定位结果。
- 把接收／校验结果、涉密审查、解析或索引、发布可见分别记录。目标端仅接收文件时，用户侧可见性不能从任务成功直接继承。
- 讨论断点和返工时，至少区分「未被接收」「接收但未入业务库」「已经形成目标对象」「已经对目标用户开放」。各阶段允许的重试、替换、撤回操作不同。
- 对部分成功的整批任务，明确已成功记录是否保留、失败记录如何补传、相同包再次提交的结果、源端和目标端均要显示什么。
- 历史审批、拒绝或删除信息是否随包传递，需要确认保留期和显示对象。是否允许后续同步授权和删除，应在首期明确列入或延后。

### 6.5 建议纳入方案评审的验收场景

| 场景 | 方案必须给出明确结果 |
| --- | --- |
| 单个允许的文库文档从源端发往目标端 | 原件和元数据映射正确，可追查双方 ID；目标归属、检测、解析、发布记录能分别看到 |
| 行业／企业／部门知识库与个人文档选错目标 | 是否拒绝、由谁改目标，如何防止把个人资料混入公共目录 |
| 同名不同内容、同一文件的第二版本、同包重送 | 三类冲突分别有行为；重复提交及重试不会无声覆写或重复入库 |
| 目标部门或人员无法映射、目标类别不存在 | 展示错误及整改入口；不隐式扩大接收范围 |
| 待检、可疑、人工审核中、驳回、解析失败 | 对每种状态明确能否发起、是否能进入目标审核、何时允许对用户可见 |
| 同批其中一条损坏、条数超限或校验失败 | 可以区分成功与失败项，回执和重试边界清楚 |
| 发起权与文档下载权分别验证 | 当前用户能阅读或下载时，仍按摆渡发起权校验；目标用户按实际有效访问权限验证列表、搜索、全文、下载和问答 |
| 有限公开文档，以及带期限的个人加授 | 可以证明试读、全文和下载的界线，审批与到期产生的效果符合目标端规则 |
| 摆渡后重新打开、切换账号或切换部门 | 可按任务、文档、责任部门和授权人追查，一方更新不会默默用错身份 |
| 撤回、删除及目标侧已经发布后撤销 | 记录删除或撤销的边界，明确是否下架、如何处理已有索引、引用和源端数据 |

## 7. 现状回归与定位索引

这组用例用于建立摆渡前的基线。前台知识库、文库用户端、文库后台以及个人中心的部门权限审核需区分场景。

| 范围 | 建议操作 | 原型基线或预期限制 |
| --- | --- | --- |
| 知识库资料索引 | 从默认行业切企业、部门；选 HR 组织；用当前范围和全部范围分别搜；清关键词 | 目录卡片、组织分组和结果数量正确；页签总数按原目录统计；清空回到当前分类 |
| 知识库个人文档 | 对通过和可疑样例点眼睛、预览、编辑、删除；取消编辑后重开；刷新 | 涉密详情可见；可疑样例不能点预览；已通过只打开占位说明；无原件下载；本页改动刷新丢失 |
| 知识库到问答 | 点击任一公共库；再打开百舸问答选择器 | 公共库点击仅提示独立问答待接入；独立问答选择器继续使用自己的八条演示来源 |
| 文库前台 | 查标题与分类；热门／最新和更多翻页；切部门和人员；开两个文档页签 | 读取当前浏览器文库记录；全文与试读均为示例；权限联动可观察。当前无权限与低权限放行缺口见第 3.4 节 |
| 文库文件管理 | 依次切经研、标准、知产、数智管理视角；换解析和涉密筛选；单个或批量删除 | 当前部门只看自己负责类型的部门上传文档；爬虫文档在权限管理中出现；筛选和操作不等同真实文件服务 |
| 文库上传 | 单类型部门和多类型部门各走一次向导；观察文件待检、无命中和可疑两条分支 | 类型跟随当前管理部门；公开方式选定后作用到文档；异步更新是原型计时，人工队列联动的缺口见后台一节 |
| 文库权限 | 同一文档对部门和个人分别设置；零权限、试读、全文、下载各验证；恢复默认和过期 | 个人有效权限按较高值；全部公开文档普通 4 级可下载，有限公开文档通过对象级全部公开获得；到期恢复默认行为以权限层为准 |
| 平台申请 | 在个人中心分别申请一项功能、一项部门知识库权限；到后台逐项审核 | 功能通过同步到功能入口；部门数据结果写入申请记录，未联动真实库访问；该流程独立于文库逐文档授权、涉密审查和三元角色变更 |
