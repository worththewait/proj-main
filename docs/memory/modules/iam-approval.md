# 角色授权审核与我的申请

## 定位与工作台

- 三元权限原型管理「用户角色关系」「用户启用／停用／删除」「角色菜单与启用／停用／删除」。相邻入口 [用户管理](user-administration.md)、[角色管理](role-administration.md)、[访问控制](access-control.md)。个人权限申请的逐项审核另见 [功能与数据权限申请](function-access.md)。
- 后台 `admin.html` 顶部「演示身份」可选管理员、审核员、审核员 2，状态存在会话 `baige.iam.actor.v1`。管理员管理账号角色和提交申请，可在两个管理页的「我的申请」右侧抽屉查看本人的申请、待审和终态，能撤回自己的待审申请。审核员进入 `admin.html#role-approval` 的「角色授权审核」，默认待审核，另有处理记录；审核员仅显示该权限导航。关联测试账号的审核员须对本人涉及的整单回避，此时可换另一位审核员。两位审核员没有角色、来源或部门分工。日志观察端暂未提供。
- 两个管理页的抽屉复用 `pages/role-approval.html?panel=1&category=user|role`，默认分类跟入口，支持切换全部／用户变更／角色变更。用 `request` 参数或哈希深链打开详情并定位对应分类、页码。后台通过 `baige:iam-request`、`baige:iam-requests-close`、`baige:iam-requests-return` 协调抽屉和焦点，独立打开管理页也能就地打开。详情回列表保留筛选、分页和滚动位置，关闭整个抽屉回管理页面触发控件。
- 分类看变更直接对象。用户管理分配角色、角色管理给多人增删同一角色都是用户变更。角色自身菜单、启停、删除归角色变更。列表支持按分类、目标关键词、变更类型筛选，全部申请和处理记录可按状态筛选。待审数量按分类计算。关键词覆盖编号、发起人、目标、涉及人员。每页默认 10 条，重置或切换筛选回第一页。申请状态 `pending` 待审核、`approved` 已通过、`rejected` 已驳回、`withdrawn` 已撤回、`invalid` 已失效。
- 「变更事项」把角色关系变化按「新增」「撤销」分两行，分别按角色 ID 去重并显示实际名字，来源在下方。窄列预览一个角色名，容器宽度达到 320px 时预览两个，`+N` 或「展开」用原生 `details` 显示完整名字，再点「收起」还原。批量按目标人去重、显示首人及总人数，用户与变更角色的对应关系在详情里查。

## 两类详情与菜单对比

- 用户变更详情先突出变更账号、所属部门和实际角色增删或状态转换。单人完整账号菜单对比默认折叠。多人逐个显示账号的增减、实际是否受影响，默认见前 6 人，其余折叠，各人可展开完整对比和查看实时权限。账号菜单取正常角色展开后的叶子并集，再包含正常账号的默认首页，停用或删除后为空。两个角色有同一叶子时只计一次，撤销其中一个角色仍可能保留该叶子。
- 角色变更详情先展示角色名称、状态变更／新增移除菜单数量、默认展开的「角色权限对比」，再显示涉及用户表（姓名、账号、部门、正常／停用）和总数，每页默认 10 人。只有一组角色菜单对比，成员只展示身份状态。状态和菜单同时改变时对比配置的菜单，状态转换单列提示。停用或删除的单独申请展示对应的可用菜单变化。
- 对比组件 `src/pages/iam-menu-comparison.js` 以同一棵树在两列渲染，树形父子缩进，复选标记只读（已授权／部分授权／未授权）。两侧共同范围为前后权限集合的并集，同一路由跨分类计算完整的子权限集合。前列标移除，后列标新增。角色对比默认展开变化支路，未变分支可手动展开。未知菜单进「历史菜单」以保留旧数据。用户待审叫「当前权限／审核通过后」，已通过叫「变更前／变更后」，无法给出实时对比时展示提交依据和申请方案。角色前列固定「变更前」。
- 用户详情的「查看实时权限」对当前账号重新读取实际菜单，弹窗以首页分类列出菜单，停用／已删除时为空并给提示。此入口是实时菜单清单，申请中的前后列对应各自时点，记录可随条件不同而产生差异。详情主区有申请原因，底部有编号、来源及提交／处理记录。历史使用提交身份，以及通过时保存的权限和状态；待审遇身份、部门或权限变化提示核对。

## 写入、冲突和终态

- `src/iam-store.js` 保存 `baige.iam.v1` 内同一份用户、角色、申请和事件，首次读取提供演示用户／角色，申请与事件初始为空。申请项包括操作、目标 ID 与名称，另存原因、来源、发起身份、时间、直接依赖和影响记录。UI 的写操作通过 `withWriteLock` 优先使用 Web Locks，支持不可用时的降级，排队期间身份变化会拒绝执行。整单批准与生效一次写入，阻止部分角色关系生效。
- 入单时必填理由，用户与角色自身各按目标互斥。关联项新增要求角色正常、可分配、用户正常（初始停用的账号首次分配另见用户管理），直接审批依赖为目标用户状态和 `stateRevision`、被操作角色状态和 `scopeRevision`／菜单、当前关系是否存在。角色自身申请依赖原角色状态／版本／菜单和正式成员 ID 集合，成员资料或状态更新会刷新显示，成员集合变化使申请失效。账号启停或删除单直接依赖该账号状态／版本。
- 待审角色菜单、启停或删除会阻止所有新增该角色的入口，同时阻挡先前已提交的新增分配单批准。可从当下详情打开阻塞的角色申请并返回原单，恢复原备注、对比折叠和滚动位置。角色单撤回或驳回后，仍有效的新增单可以按当前结果审批。角色单批准改变了直接依赖时，新增单失效。已拥有的角色可继续发起移除。由于角色成员变化属于角色申请的直接依赖，先批准移除可能使有该成员的角色申请失效。零成员纯菜单直改会主动使使用旧配置的待审分配单失效。
- 只有管理员可发起或撤回。审核资格按当前审核身份及发起人、受影响用户判定。切换审核员后，打开的详情及时刷新按钮和回避提示。批准意见可空，驳回必须填写原因。批准前 `reviewPreview` 提供待审最新影响和 token，点击时用 `reviewRequest` 复核同一 token。显示后若其他角色导致合并菜单改变，或相关身份、状态信息变化，刷新对比并要求再次点击。依赖变化或明确的失效事件进入已失效；被角色待审阻塞的有效单仍可查看、撤回或驳回。撤回、驳回、失效不应用权限。

## 快照兼容和回归入口

- V3 用户变更保留直接依赖与逐用户当前／拟生效菜单及状态。V4 角色自身变更保存角色变更前后菜单和成员身份状态，不对每个成员做角色并集。`impact` 为提交时快照，`approvedImpact` 为批准当时的影响快照。用户资料变更按新旧身份对照，历史优先使用提交时身份。角色详情沿用角色配置快照，过往成员信息能追溯。
- 兼容完整 V2／V3 存量审批。V2 用户状态类读取补充快照中的账号状态，角色类按角色菜单和成员 ID 核对。无法验证的旧单显示缺少权限快照并禁用批准，允许合法的撤回和驳回，重提生成新快照。浏览器存储和演示身份切换提供原型流程，未集成服务端登录、审批、授权策略或审计页面。
- 主入口 `pages/role-approval.html`、`src/pages/role-approval.js`、`role-approval.css`、`iam-menu-comparison.css`、`src/pages/iam-management.js`、`admin.js`。回归入口 `tests/iam-admin.test.cjs`、`tests/iam-approval-ui.test.cjs`、`tests/admin-shell.test.cjs`，包括待审互斥、角色阻塞、批量整单、双审核员回避和重绘、成员轻量快照、兼容、树结构、详情状态、紧凑角色预览。
