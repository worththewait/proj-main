# 角色管理

## 定位与入口

- 管理员从 `admin.html#roles` 进入 `pages/role-admin.html`，维护角色资料、菜单树和正式成员。角色自身菜单、状态和删除走角色变更分类，角色成员的增加与撤销按目标用户进入用户变更分类。审核规则见 [角色授权审核](iam-approval.md)。
- 页面由 `src/pages/role-admin.js`、`user-role-admin.css`、`iam-role-editor.css` 实现。管理共用 `src/pages/iam-management.js` 与 `src/pages/admin-pagination.js`。菜单来源 `src/data.js`、`src/feature-config.js` 和 `src/iam-menu-catalog.js`。

## 角色资料和菜单

- 角色列表按名称、权限字符、正常或停用筛选。每页默认 10 条，列出角色 ID、名称、权限字符、顺序、创建时间、状态和操作。待审核记录从角色名下进入。列表只用「正常」和「停用」呈现已生效状态。
- 新建填写名称、权限字符、顺序（1–999 整数，默认 1）和初始状态，直接创建空菜单、空成员的角色。已预设的权限字符保留给系统，提交时区分形式校验与角色保护。`updateRole` 只写名称、权限字符、顺序、备注，菜单、成员和状态使用专门的 store 入口。
- 编辑使用宽弹窗，左侧角色资料、状态两段按钮和备注，右侧菜单权限的可选树和已选清单。以客户端首页分类和子功能为目录。支持全树展开或收起、输入搜索、父子联动开关、复选框半选、全选、清除。全选与分支操作只影响当前搜索的可编辑叶子，清除作用于全量可编辑叶子。首页默认可用且锁定，不计为新菜单授权。系统预设后台权限只读，不能通过角色编辑新增或删除。保护角色（超级管理员及保留权限字符的角色）只可查看信息、菜单和成员，不能以该入口授予成员。
- `src/pages/iam-role-menu-picker.js` 保留原始旧版整组键，进入再保存以及恢复原勾选时保持原键。部分撤销旧组时转换为明确叶子键，未知旧键和锁定项继续保留。比较时用 `BaigeIamMenuCatalog.expand` 去重并展开等价集合，显示同一集合的不同键形态不触发审批。

## 保存与涉人规则

- 单独更新资料立即保存。只改菜单，且角色没有正式成员（含停用成员），直接保存并记录 `role-menus-saved`。此时使用旧配置的待审新增分配申请将失效，保存前提示影响张数，需按新配置重新分配。直接保存先核对同角色自身变更互斥和最新成员，不能把已有成员的变更当成空角色直接保存。
- 已有正式成员时菜单增减须送审，哪怕所有成员均停用。角色启用、停用、删除始终送审，包括零成员角色。角色编辑同时改变状态和菜单时提交一张申请，批准后一起生效。该角色自身有待审申请时可保存资料，权限和状态需先处理原申请。审核通过后停用不拆成员关系，删除才清理所有用户的该角色关系。
- 编辑提交前只显示涉及用户表（姓名、账号、部门、正常／停用，每页默认 10 人）和必填申请原因，不重复显示权限差异。提交后在申请详情显示角色前后菜单对比。成员范围取 `users[].roleIds` 的正式成员，不计待审新增，包含停用成员。
- `previewRoleChange` 提供变更种类、是否审核、待失效申请 ID、涉及用户和 token。`saveRoleEdit` 核对原始菜单和状态，再根据最新成员、身份状态、待审申请、计划菜单校验 token。若变化则提示重新核对。资料、申请或直接保存采用同一次持久化写入，校验失败不会只更新资料。

## 成员管理与数据

- 「分配用户」弹窗区分正式已生效／已暂停、待审新增，以及正式人员的待审变更，待审均可查看原申请。支持以账号或昵称、手机号查找，并可单个或批量申请撤销正式成员。用户已有待审权限变更时先处理原单。撤销须说明原因，批准才移除双向关系。
- 「添加用户」选择尚未分配的正常账号，明确跳过同角色已送审的新成员，并禁用存在其他待审用户申请的账号。角色已停用、有角色自身待审变更或受到预设保护时不提供可执行的添加。确认申请原因后，批量请求进入用户变更。成员表和候选账号表默认每页 5 人，表头只作用于当前页，已选可跨页保留。
- `baige.iam.v1` 保存角色基础资料、角色菜单、账号与角色关系、申请和直接变更记录。角色权限范围更新递增 `scopeRevision`，供依赖该角色变化的审批判定。选项、变更和角色审批为本地演示，未调用后端。
- 回归入口 `tests/iam-role-menu-picker.test.cjs`、`tests/iam-admin.test.cjs`、`tests/iam-approval-ui.test.cjs`。覆盖选择和历史键，零成员直改、停用成员仍送审，首次新增先批准、待审阻塞、角色保护和成员分页展示。
