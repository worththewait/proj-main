# 用户管理

## 定位与入口

- 三元权限的账号维护和角色分配入口。管理员从 `admin.html#users` 打开，支持独立访问 `pages/user-admin.html`。审核员在后台只进入角色授权审核，直接访问用户页也受到页面初始化时的身份检查。
- `src/pages/user-admin.js` 管理本页交互。`src/pages/iam-management.js` 共用状态开关、待审提示、申请提交弹窗、我的申请抽屉和焦点返回。业务判定统一在 `src/iam-store.js`。审理与快照见 [角色授权审核](iam-approval.md)，账号生效菜单见 [访问控制](access-control.md)。

## 查找与维护资料

- 左栏组织树支持按部门名搜索、展开收起、点击选中及再次点击取消。选择任意节点按该节点及后代部门匹配。搜索部门树只缩小显示树节点，不替代右侧用户筛选。
- 用户栏支持按账号或昵称、手机片段、正常或停用筛选，查询和重置回到第一页。表格有用户账号、昵称、部门、脱敏手机、创建时间、正常／停用开关和编辑、申请删除、重置密码、分配角色。待审状态以账号下方的「待审核」链接进入原申请。每页默认 10 条。
- 新建和编辑表单收集昵称、部门、手机、邮箱、账号、密码、性别、状态、岗位、角色和备注。新建校验昵称、部门、手机、账号、密码、至少一个角色和非空申请原因。密码用于原型表单演示，账号记录没有密码字段，重置密码为确认和提示演示。普通资料保存即时生效。编辑时显示现有状态，启停由列表开关处理。
- 角色为可多选下拉，已选角色显示为可删除的标签。角色选择相对打开表单时的正式关系产生增删差异。编辑只有差异出现才展示必填的申请原因（240 字上限），恢复原选择后清空原因。仅资料改动时按钮为「保存资料」，角色变更时为「保存并提交审核」。
- `createUserWithRequest` 一次保存账号及初始分配申请，失败不会留下账号。真实关系初始为空。账号可初始停用，此时仍必须至少选择一个正常可分配角色，初始分配是停用用户新增角色的唯一例外。初始角色申请撤回或驳回后，资料记录保留且角色不生效。`saveUserEdit` 校验打开时的正式关系，资料和申请一起写入，失败保留原资料。申请提交成功后，普通资料已保存，角色关系等待审核。

## 角色分配与生命周期

- 用户侧分配入口 `新建用户`、`编辑用户`、`用户管理 · 分配角色` 与角色侧批量添加／撤销入口共用 `membership`。分配弹窗默认每页 5 条，列出角色 ID、名称、权限字符、创建时间、授权状态。表头只勾选本页可新增角色，跨页保留草稿。现有角色逐项取消勾选申请撤销，选择和取消仅改变草稿。
- 正常账号可新增已启用、未拥有、非系统预设的角色。已拥有角色在账号或角色停用时显示「已暂停」，可申请移除。目标角色配置、状态或删除申请待审时，所有新增入口暂停该角色并显示原申请入口，已拥有角色仍可申请撤销。同一目标用户已有任何待审角色或状态单时须先处理原单，不同用户可同时申请同一角色。
- 双向关系由批准时同步维护 `user.roleIds` 与 `role.userIds`。启停不拆除关系。审批撤销角色后可以剩零角色。删除账号始终审批，批准后清理各角色的成员关系。预设审核员对应账号禁止停用和删除，详情仍可查阅。
- 启用与停用只呈现「正常」和「停用」。`userStatusRequiresApproval` 仅在 `roleIds` 是明确的空数组时允许状态直接生效，存在停用角色也属于有角色，缺失关系字段同样走审核。直接启停仍受用户待审互斥约束，应用后递增 `stateRevision` 并记 `user-status-saved` 事件。已有角色的账号启停须填申请原因。共享 UI 通过 `expectedApproval` 和写锁按保存时的最新关系校验路线，如果条件变化提示重试。

## 数据与回归入口

- `baige.iam.v1` 浏览器存储包含 `users`、`roles`、`requests`、`events`。部门树随代码发布，页面订阅 store 与 storage 变化重绘。此处按钮和身份为原型演示，账号验证、密码管理、组织和存储均没有后端接入。
- `tests/iam-admin.test.cjs` 覆盖新建原子保存、初始停用、资料与角色联动、删除与角色关系清理、账号有无角色的启停、互斥和并发条件。`tests/admin-shell.test.cjs` 核对后台入口，`tests/sidebar-permissions.test.cjs` 核对批准与停用后导航变化。
