# 百舸文库（客户端阅读与后管文档权限）

- 状态：共享浏览器文档元数据的原型。客户端 `index.html#library` → `pages/library.html`（只露出文库首页）；后管 `admin.html#files`、`admin.html#perm`、`admin.html#category`，前两者 → `pages/library-admin.html?embed=admin&view=files|perm`，第三者 → `pages/library-category.html`。独立后管页默认文件管理。
- 主实现：`src/pages/library.js`、`pages/library-admin.html` 页内控制器、`src/library-store.js`、`src/library-data.js`。来源和详细生产语义见 `docs/知识库与百舸文库需求交接.md` 第 3–5 节。最近核对 2026-11-19，当前提交 `9da2807`；文库相关代码相对 PRD 核对基线 `ebf6e71` 未变。本文件先记代码现状，末尾单列正式需求与缺口。

## 业务对象和职责

- 对象是单篇文档，区别于客户端知识库的库卡片、原问答的来源 ID、门户「最新动态/我的收藏」、个人功能申请、IAM 账号菜单。百舸文库后台保留自己的涉密表和文件操作约定，不跟随前台文件表组件修改。
- 初始八类型：智库成果、船舶标准、行业专利、三方研报、规则规范、专业书籍、期刊论文、其他；并非固定枚举，可在分类归属类型库中增删。六个组织部门可作为授权对象，其中初始经研（经济研究中心）管智库成果、三方研报，标准（船级社规范所）管船舶标准，知产（技术经济中心）管行业专利，数智（情报研究所）管规则规范、专业书籍、期刊论文、其他。未知分类当前规整到「其他」（含删除其他类型后的兼容行为仍待定）。管理归属由配置确定，来源独立为 `upload | crawl`。
- 后台「当前部门」来自分类归属配置：负责至少一个分类的部门都可进入，已有四个视角保持原顺序，新接手部门追加在后。默认优先沿用可管理的前台部门，否则经研。文件管理只展示本管理部门的上传文档；权限管理展示本管理部门负责分类的上传与爬虫文档；本部门已无负责分类时文件管理空态提示「本部门暂无负责分类」，仍可作为授权对象。分类归属配置见 [分类归属](library-category.md)。

## 客户端检索与阅读

- 首次共享文档种子按标题去重合并 24 篇首页样例、40 篇权限样例、3 篇文件样例。页面初始化读一次 `loadDocs()`，只保留涉密 `passed / approved / stored` 且解析非 `failed` 的记录；因此 `passed + parsing` 可出现。刷新用于重新取数。
- 默认「智库成果 / 热门」，首页按热度或时间排序，分类首页最多 6 卡，更多打开全量列表。顶部分类筛选默认全部。普通检索用标题、分类、机构、作者、文献类型的子串匹配；AI 语义检索是本地拆词和权重排序。结果区与更多列表每页 12／24／48，默认 12，工作区侧边搜索 8／16／24，默认 8；侧边 AI 按钮沿用普通搜索。
- 阅读工作区左侧可折叠文档搜索、中间文档预览、右侧可收起和调整宽度的问答；打开多文档可用页签和「已打开」切换，关最后一页签回列表。全文为六页共享示例，试读为前两页。全文权限才可发单文档问答，关键词演示回答、展示引用标号和示例页跳转；历史按文档内存存放。下载依据归属/生效等级给提示，原件与真实下载记录待接入。
- 前台有两处待补齐：0/1/2 的列表和预览限制未严格落实，可能显示低权限卡片或样例试读，历史面板可有预置答复。文档映射保留权限与到期字段但漏掉 `publicDept / publicPerson`，导致数据层已授予全文与下载时，有限公开文档仍可能显示试读。生产验收需实测有效级别的检索、元数据、试读、原件和问答分层。

## 文件管理、上传与双状态

- 文件表含勾选、文件名/格式图标、来源、文档类型、版本、创建时间、解析、涉密、最近更新、操作；按时间范围、解析、涉密、文件名筛选，查询回首页，默认每页 10，可选 24/48。行级和批量删除会再次判断管理范围；实际按 DOM 当前勾选项删除，表头当前未把所有行置为选中。普通预览、下载和编辑为提示占位；筛选时间字段当前主要使用 `date`，部分行操作按文件名查找，生产应用 ID。
- 三步向导是「上传文件 → 补充信息 → 完成录入」。界面宣明 Word/PDF、单份不超过 50 MB，实际插入三条固定演示文件并跑定时进度。信息可改显示名、版本、选封面；右侧仅能选当前部门职责内单一文档类型，只有一项则自动填。公开方式默认全部公开；分类与公开方式按批次设置。实际落库是元数据，向导指定的封面、文件本体、大小和修改的版本未完整写入。
- 解析轴 `unparsed → parsing → parsed`，另有 `failed` 筛选。涉密轴 `detecting → passed / hit`。通过时开始解析；可疑时停留未解析，在状态旁小眼睛看命中和流转。可疑项可「取消上传」（删记录）或继续送审 `submitted`；审核中只关闭，驳回 `rejected` 留有重新上传占位。
- 当前后管只有自动检查与可疑送审状态。旧页内企业/部门/个人 `KB_DATA` 审批演示用各自样例队列，现代文件的送审不会进入该队列。人工审批回写共享文档、重试、刷新恢复、服务端解析与入库发布待接入，不能以状态标签当作生产审核凭据。

## 文档授权计算和页面

- 左侧选部门或展开到个人，当前管理部门及人员隐藏；个人显示部门基础、个人加授、生效。权限类型为 `0 无权/无额外加授、1 可搜索、2 可见元数据、3 可在线读、4 全文和下载`，高等级包含低等级。归属部门总为 4；外部门通常默认 3，有限公开的普通等级 3 仍试读。个人权限只能提高部门基础，取 `max`；个人 0 清除个人覆盖，部门 0 显式禁用。
- `accessMode = public | limited` 是整篇的发布方式。全部公开下按对象配 0–4。有限公开的数值等级最多 3；对特定部门/个人全开需额外标记 `publicDept/publicPerson` 加等级 4，其他对象照旧。配置界面只有全部选中项均有限公开时展示目标级公开开关；混合批次时普通部门数值对有限公开在存储层封顶 3，个人普通加授 4 遇有限公开会拒绝。个人合法等级须高于选中文档的部门基线。
- 有效期可选永久、7、30、90 天、自定义日期当日 23:59:59（浏览器时区），0 不设置有效期。读时检查是否过期，后台约每 30 秒清理覆盖；部门过期恢复分类发布默认，个人过期恢复部门继承。「恢复默认」删除覆盖，和写 0 的「不授权」要区分。
- 按文字（标题/机构/作者/分类/时间）、来源、部门职责内分类、公开方式筛选。默认每页 12，可选 24/48。选中跨页保存，表头仅选当前页。支持单项、批量选中、批量当前筛选全部、恢复当前管理范围默认或清除个人加授；切换授权对象清勾选和分页。企业树根当前以 `enterprise` 单个键写入，没有展开部门及前台继承，企业广播授权待接入。

## 正式目标与原型差距

以下为本轮 PRD 的交付目标/开发补齐项，不能据此宣称已上线。分类归属详细决定及差距只维护在分类归属主档。

- 文件身份用稳定文档 ID + 文件版本 ID；标题、实际格式/大小、原件、封面、版本、上传人时间、机构作者和业务日期分别保存。查询显示值应能从详情回读，操作不能靠文件名定位。类型生产化采用稳定 ID，部门人员来自组织系统。
- 文件管理保持自己的后台列表，不套前台统一涉密列表。默认每页 10 条，可选 10/24/48；查询回首页，日期含首尾，文件名支持子串。表头选择当前页，删除前确认实际选中数；跨页选择策略列入 P07。权限管理默认 12 条，可选 12/24/48，跨页勾选保留；切换授权对象清空分页与勾选。
- 三步录入：选择文件 → 补充信息 → 完成录入。现有 Word/PDF、单份 50 MB 是界面基线，正式扩展名和批量上限见 P03。逐文件名称/版本/封面独立回显；业务类型与公开方式当前按批次设置。只可选现行负责类型；无负责类型停止新录入，提交重验权限、类型归属、配置版本。真实文件上传、失败逐项处理、完整元数据落库尚待接入。
- 每个文件版本独立检测：检测中 → 自动通过 → 解析；或检测中 → 涉密可疑 → 上传方继续送审 → 审核中 → 人工通过后解析 / 驳回。可疑取消、驳回重录和技术失败重试分开。人工结论要保存审核人、时间、意见、同版本依据；待办重复提交/处理必须去重。当前送审尚未接通旧样例审批队列。
- 解析成功关联真实预览、文本、页数、检索索引、引用位置。检测通过、资源可用及发布条件同时满足才开放；发布与解析状态独立。刷新、离开页面或关闭浏览器后，服务端任务持续运行，再进入可查进度与失败原因；迟到的旧版本结果不得覆盖新版本。自动发布还是人工确认见 P02。
- 普通读者正文、下载、问答及引用均按文档状态和有效权限逐请求校验，先过滤后排序计数分页。`0` 不可见；`1` 仅搜索元数据；`2` 列表和详情元数据；`3` 全部公开可全文/问答，有限公开默认前两页试读；`4` 全文/问答/原件下载。有限公开 1/2 级试读仍待 P01 定案。当前低等级限制、真实正文/引用/下载、目标级公开标记映射与问答持久化都有缺口。
- 保持部门基础 + 个人正向加授的计算，不用角色菜单并集替代文档授权。归属自动能力与独立授权分别记录；交接、恢复默认、过期后重新计算。`setPermissions` 会标记 `explicitDept`，实际 UI 的 `setGrantMode` 未同步此标记，`clearPermissions` 也未清除标记，不能将独立授权保留视为所有 UI 路径都已闭环。
- 原件下载只有文件存在、状态和权限满足才成功，不能用 toast 替代下载事实。失败不展示成功回执。读取过程中到期、撤权、切身份、版本替换或下架，后续请求使用新状态；无权错误不泄露正文/命中片段。
- 与知识库阅读/问答或数据摆渡联动时传来源与版本，目标系统重新核验。`9da2807` 最近改动属于数据摆渡任务及后台导航，未修改文库相关实现；不据此推断文库 store 已接通摆渡。正式导入的身份/类型映射、目标归属、审核结论认可、原件及授权对接待 P08 确认。
