# 分类归属（部门列表 + 类型库）

- 状态：后台可操作原型。目标为平台指定人员配置，确认后直接生效、无需审核；当前分配弹窗保存直接写入，尚缺后果确认。部门管理员只在业务页处理本部门文档。入口 `admin.html#category` → `pages/library-category.html?embed=admin&actor=&kind=&by=`。相邻模块 [百舸文库](library.md)、[访问控制](access-control.md)。
- 主实现：`src/library-category-store.js`、`src/pages/library-category.js`、`library-category.css`。最近核对 2026-11-19 当前提交 `9da2807`，本模块相对 `ebf6e71` 未变。布局为部门列表 + 类型库；此前“固定八分类表”“按部门分组表”两版已作废。以下为代码现状，末尾单列已确认目标和缺口。

## 对象与默认

- **一份类型库 + 一张部门列表**：类型库管类型的增删；部门行的「分配类型」从同一份类型库多选，勾选即由本部门负责。
- 初始八类型：智库成果、船舶标准、行业专利、三方研报、规则规范、专业书籍、期刊论文、其他。首次进入沿用既有分工：经研中心（经济研究中心）负责智库成果、三方研报；标准中心（船级社规范所）负责船舶标准；知产中心（技术经济中心）负责行业专利；数智中心（情报研究所）负责规则规范、专业书籍、期刊论文、其他；动力研究院与国际航运研究中心暂不负责类型。
- 页面：标题下「部门列表」面板，右上「类型管理」（类型库）；表格三列（部门、负责类型、操作）。负责类型以浅蓝标签展示，没有则显示「暂未负责类型」；行尾「分配类型」打开多选框。有未分配类型时，表格末尾多一行「未分配类型」，灰色标签，右侧提示「在部门中勾选」。底部一行汇总（共 N 个类型、已分配、未分配）。
- 表格下方「最近调整」显示最近三条：新增类型、删除类型、交由某部门负责、改为未分配、单个类型调整。

## 两个弹窗

- **类型管理（全局）**：输入框 + 「添加」新增类型（2–12 字、不可重名），列表逐行显示「类型名 / 负责部门 / 删除」。删除前确认；该类型下还有文档时拒绝并提示「「X」下还有 N 篇文档，暂不能删除；可先调整文档类型」。
- **分配类型（部门）**：标题为「某部门 · 分配类型」，勾选框来自类型库（两列），每项右侧灰字提示「现由 某部门 负责」或「未分配」，已勾选项为蓝框蓝底。保存即提交多选结果：勾选的归本部门（原属其他部门的会自动转移），取消勾选的转为未分配。
- 存储写接口支持 `expectedVersion`。部门分配取打开弹窗时的 `state.version`；类型新增/删除在动作时取当前 `snapshot().version`，并不是打开类型管理时的版本锁定。发生版本冲突时提示「类型配置已被其他配置人员修改，请刷新后再确认。」。当前均为本地存储逻辑，不能代替服务端并发事务。

## 权限与生效范围

- 配置入口与保存共用一个平台级权限：`canConfigure()` 只认平台指定人员（演示身份 `kind === "admin"` 或 id 在 `PLATFORM_EDITORS`）。无权限时保留标题与说明，只显示「没有配置权限」，面板隐藏；后台导航对审核员隐藏。
- 按类型整体生效，不逐篇手动调整：数据层 `uploadsForDept / managedDocs` 按 `ownerDept` 过滤，前台归属权限按当前归属计算。管理 UI 另按当前负责类型筛选，且管理部门下拉只包含仍负责至少一个类型的部门。原部门若已无负责类型，会被排除或显示「本部门暂无负责分类」；这与未分配存量可继续管理的目标仍有差距。
- 上传向导的分类选项、管理端的「管理部门」下拉都来自同一份映射；新接手的部门自动出现在下拉中（四个原有视角保持顺序，新部门追加在后）。
- 类型库是权威来源：`BaigeLibraryStore.categories`、`managerTypes(dept)`、前台 `pages/library.js` 的分类导航与检索下拉都以 `store.types()` 为准，新增的类型立即出现，删除的类型立即消失。

## 未分配类型

- 允许类型没有负责部门（部门多选里取消勾选即转为未分配）。未分配类型不在新上传可选范围，类型库及页面未分配行仍保留该类型。
- 数据层已有文档不丢：`normalizeDoc` 里 `ownerDept = ownerFor(category) || previousOwner`，存量保留原部门字段和 4 级；`uploadsForDept / managedDocs` 仍可按原部门取到。直到分配给新部门才再交接。
- UI 缺口：当前类型筛选与管理部门下拉可能隐藏这些存量；不能把数据层保留写成用户已能继续管理。目标要求原部门有稳定入口查找、维护、授权，并显示「类型未分配 / 存量保留归属」。

## 数据与持久层

- 键 `baige.library.category-owner.v1`：`{version, types:[名称], owners:{类型:部门|""}, changes:[{action:"create"|"delete"|"assign"|"unassign"|"move", at, by, category, from, to}], updatedAt, updatedBy}`。
- 读取兼容旧结构（只有 `owners`）：以种子为底、把自定义类型追加在后；新结构里 `types` 为准，删除过的类型不会再回来。
- 保存写库后派发 `baige:library-category`；文库数据层监听该事件与其他标签页 `storage`，丢弃文档缓存。缓存失效不等于所有旧页面的上传/授权提交已重验范围，最后提交端的现行归属校验仍待补。
- 变更记录保留最近 50 条；`changes(limit)` 返回倒序。

## 权限计算（不可退化）

- 文档归属由类型映射推导（`ownerFor(category)`），不写死。归属部门为 4 级；归属变化时以 `autoOwner` 与 `explicitDept` 区分来源，收回自动 4 级（回普通等级 3）。`setPermissions` 标记显式部门授权并有保留测试；实际授权 UI 调用的 `setGrantMode` 尚未写同样标记，`clearPermissions` 未清掉标记。所有路径一致地保留独立授权属于目标，尚非完整实现。
- 有限公开文档交接后：原部门转为试读（`isTrialAccess` 为真），新部门全文与下载；公开方式、单独授权、涉密与解析状态不变。
- 验收锚点：`tests/library-category.test.cjs` 覆盖部门列表页面、类型库增删、名称校验、部门多选（勾选转移 / 取消转未分配）、未分配存量文档、版本冲突、权限交接与显式授权保留、管理范围跟随；`tests/library-store.test.cjs` 覆盖原有归属与权限规则。

## 已确认目标与 PRD 对照

- 用户明确：文档类型负责部门可配置，不能把此权交给部门人员；在百舸文库后台单独设「分类归属」页面，调整不走审核，提交前弹窗提醒后果。平台菜单操作权与文档授权及涉密审查相互独立。
- PRD V1.1 第 03–04 节 `C01–C14` 是本模块开发对照，第 15 节 `T01–T11` 是主要验收；文档交付背景和全部待确认项见 [百舸文库](library.md)。不要把本轮“更新记忆”理解为已经实现 PRD 缺口。
- `C01–C07`：统一类型库，一部门可多类型、一类型最多一部门；新增去首尾空白、2–12 字、唯一、末尾追加且未分配；有任何文档的类型不可删除。类型增删逐项生效，「完成」只关闭；部门多选取消/关闭放弃草稿，保存整批生效。类型空态和无实质变化须给明确反馈。权限校验覆盖页面与读写接口。
- `C08` 后果确认（待实现）：分配弹窗点击保存 → 计算实际新增负责/交接/转为未分配 → 逐项列出类型、原部门、新部门、现有文档数量 → 点击「确认调整」才保存。取消确认返回原勾选草稿，不丢已选项。影响中说明旧部门管理权/自动下载权转移、新部门接手、有效独立授权保留、未分配停止新录入但保留存量归属。
- `C09–C12`：确认后直接生效，失败保留草稿；存量与未来同类文档统一跟随新归属，上传来源/原件/公开方式/审核解析状态不因交接改变。旧部门仅收回自动归属能力；独立部门/个人授权及期限继续计算。未分配存量保留原部门管理直到再分配。
- `C13–C14`：配置版本在最终确认时重验，冲突重新核对最新分工；上传、编辑、删除和授权最终提交也校验现行归属。记录类型、前后部门、动作、人、时间和版本，变更和留痕一起成功才回执成功。最近 3 条/存 50 条只是原型，正式留存见 P09。

## 尚未完成及验收边界

- `saveDept()` 当前直接调用 `setDepartmentTypes()`，无影响详情和二次确认；不能称为已满足 C08。
- 有文档禁止删只在页面 `removeType()` 的 `docCounts()` 检查；底层 `removeType()` 未检查文档引用。正式接口需同步检查引用和配置版本，拒绝并发新增文档导致的误删。
- `canConfigure()` 依赖 URL 演示身份；数据层写方法未做生产授权。正式系统从可信登录身份校验平台配置权和组织范围，不从请求部门或 URL 获取权限。
- 未分配 UI 管理入口、实际授权保存/清理路径的来源标记、旧页面提交范围复核需补齐；当前缓存事件和单元测试不能替代这些验收。
- 类型当前以名称作 key、部门为内置六项；稳定类型/组织 ID、组织变动接管和摆渡映射须与 P08 对齐。改名、排序、删最后一类/其他及全空策略未确认（P10）。
- 2026-11-19 既有文库相关四组测试 32/32 通过，其中本模块主要是数据层测试和静态结构断言。后果确认、未分配存量 UI、真实服务权限/并发、独立授权 UI 连续交接需另做端到端验收。
